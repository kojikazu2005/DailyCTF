## 問題概要
フェルマーの最終定理によると、3以上の整数 N について、 A^{N} + B^{N} = C^{N} を満たす正整数 (A, B, C) の組は存在しません。
- 今回はN=3の場合で上の等式を満たすことができればFlagを得ることができる。
- 数字の0~9と**-**以外は使用できなくなっている。また、0以下を入力するとInvalidと帰ってくる。
- A, B, Cを入力するとそれぞれ3条を計算され、等式を満たすとFlagが変える。

```
ef sanitize(txt:str):
    txt = re.sub(r'[^-0-9]', '', txt)
```

## 試行錯誤
1. 小数や分数を入力して出力を調べた
少数であれば、N=3で解が見つかると予想した。
しかし、使用可能な文字が0~9の数字と-のみなので小数点が使用できなかった。
 　
2. マイナスが利用できるので1-1などを入力して0を入力できないか調べた
0以下の値を入力するとInvalidになるのになぜ**-**のみ使用することができるのか?
Aの値に入力に`1-1`を入力すると1以上という制約を回避できるのではないかと考えた。
残念ながらこの場合もInvalidと出力された。
 　
3. 丸め誤差や情報落ちなど計算によって等式が成り立つかどうか調べた
非常に近い値や絶対値の差が大きい値を入力すると誤差が発生することで等式が成り立つかもと考えた。
だが、`txt[:3]`で入力された数字を上から3桁までに削られるので、誤差による方法は使えなかった
　
4. CIBE()の計算方法が安全かどうか調べた
今までの方法では行き詰まったのでコードを読み別の方法を探した。
CUBE()関数を見ると3乗を計算する普通の方法なら`(x)*(x)*(x)`だが、今回のプログラムは`(x*x*x)`で記述されており、入力に**-**含めた式を入力すると計算の優先度を変更できると考えた。
入力に**2-1**のように式を入れると3乗の計算が`(2-1*2-1*2-1)`になるので`2-2*2*1-1=-3`となり,(2-1)^3と値が異なる。
A,B,Cのそれぞれの入力にa-b,c-d,e-fを入力すると`(a-2*a*b-b)+(c-2*c*d-d)=(e-2*e*f-f)`になり、等式が成り立つように総当たりを行った。
試行錯誤の2.のように 出てきた値の組み合わせ(a=1, b=1など)から計算結果が0にならず、`txt[:3]`を満たすよう`"input("A> " 2-1)"`に1桁の数の組み合わせを選択すると等式が成り立つ。


```python
for a in range(10):
    for b in range(10):
        for c in range(10):
            for d in range(10):
                for e in range(10):
                     for f in range(10):
                        if (a-b>0 and c-d>0 and e-f>0):
                            if(a-3*a*b-b+c-3*c*d-d == e-3*e*f-f):
                                print(a,b,c,d,e,f) 
                                break
```

選択した値を入力するとFlagが手に入った。

```

B> ?-?
C> ?-?

```
## まとめ
今回は入力に**-**を使用できることを利用して式を入力した。
CUBE()関数の計算方法を悪用することで計算順序を変更することで解を見つけることができた。
CUBE()関数のマクロ引数が
`CUBE(x) ((x) * (x) * (x))`
のように括弧で囲まれておらず、式を渡した際に演算子優先順位が崩れることに気づいたことが大きかった。
プログラムでは負の数を表すマイナスと減算を表すマイナスを区別することができないことが、重要であった。
